# Модуль сопоставления заказов маркетплейса с выгрузкой 1С

## Требования
* **PHP 8.1+**
* **Composer** (для автозагрузки)

## Быстрый запуск
1. Установите зависимости автозагрузчика:
   ```bash
   composer install
   ```
2. Запустите скрипт сверки (по умолчанию используются файлы из папки `data/`):
   ```bash
   php index.php
   ```
3. Для запуска с произвольными файлами передайте пути аргументами:
   ```bash
   php index.php [путь_к_заказам.json] [путь_к_номенклатуре.csv]
   ```

## Архитектурные решения и обработка аномалий данных

На основе анализа входящих файлов данных реализованы следующие бизнес-правила:

* **Объединение дублирующихся карточек 1С:** В файле номенклатуры артикул `TS-1017` продублирован двумя строками (с остатками `55,000` и `7,000`). Парсер определяет дубликат ключа и суммирует доступный остаток до `62`, предотвращая ложный дефицит.
* **Игнорирование отмененных заказов:** Заказы в статусе `cancelled` (например, `MP-24027`) автоматически помечаются как `ИГНОР` и не расходуют остатки со склада.
* **Исключение дубликатов заказов:** При обнаружении заказов с одинаковым идентификатором (например, повторный вызов `MP-24009`), первый заказ принимается, а копия получает статус `ОТКЛОНЕН`.
* **Контроль дефицита с накоплением итога:** Складские остатки уменьшаются динамически в процессе обработки цепочки заказов. Если товара не хватает, заказ получает статус `СТОП` с указанием объема дефицита.
* **Отказоустойчивость обработки (Fault Tolerance):** Позиции с отсутствующими обязательными полями (например, товар без цены в заказе `MP-24030`) изолируются. Информация о сбое пишется в ежедневный лог (`logs/logs_YYYYMMDD.log`) с сохранением читаемой кириллицы, а конвейер продолжает работу со следующими заказами.

## Исправление багов в файле OrderTotal.php

В модуле расчета итогов устранены 3 логические ошибки:
1. **Метод `subtotal`:** Убрал ошибночное приведение типов к int, чтобы не было потери копейки в ценах
2. **Метод `vatIncluded`:** Изменил формула на выделение НДС из полной стоимости (умножение на 20 и деление на 120). Сумма налога считалась неправильно и получалась больше, чем нужно
3. **Метод `calculate`:** Считать НДС нужно от общей суммы с учетом скидки. При применении скидки налог НДС ошибочно рассчитывался от полной стоимости без учета скидки
